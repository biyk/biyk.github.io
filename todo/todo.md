### Устойчивость к сбоям (сеть / битые данные)

Главный риск: транзиентная сетевая ошибка или мусор из API «валит» всё приложение и стирает локальные данные.

1. **Чтение не должно возвращать `[]` при ошибке сети.** `fetchSheetValues` (google.js:854-891) при ошибке возвращает `[]` — `getAll` считает это данными: `columns[list] = undefined`, `setCodes` очищает коды, `initTodos` кладёт пустой список в store и в `localStorage['todo-list']` (todos.js:82-93). Одна ошибка сети → стёртые данные. Правка: при ошибке возвращать `null`/бросать; `getAll` не трогать `columns`/`codes`/кэш; `initTodos`/`initHero` при ошибке чтения оставляют текущее состояние.
2. **Каскад от п.1**: `getAll` на `[]` пишет `sessionStorage[…/columns]` как `'undefined'` — следующий `JSON.parse` в `addRow`/`addRows` бросает; `new ORM(undefined)` в `initTodos` падает (TypeError в `getFormated`) → необработанный rejection.
3. **`formatData` падает на битых строках** (google.js:330-341): `e[1][0]` — TypeError при пустой ячейке; `JSON.parse` на мусоре — throw. Обернуть, битую строку пропускать.
4. **`listEvents` без try/catch** (calendar.js:18-25): из-за этого падает `taskAgent` (setInterval без обработки → необработанный rejection каждые 60 с), `mounted`, `toggleTodo`, `setTaskToCalendar`. При ошибке — логировать и продолжать со старыми событиями.
5. **Ретраи с backoff** для читающих запросов (2-3 попытки) — gapi сам не ретраит.
6. **Запись не должна глотать ошибки**: `addRawValues`/`addColumns`/`updateRow` ловят и `console.error` (google.js:102-104, 148-150, 202-204) — вызывающий «не знает», что запись не прошла; `addRow` после неудачной записи чистит кэш и задача молча пропадает из UI. Пробрасывать ошибку наверх, показывать пользователю.
7. **`updateRowByCode` при сбое refresh не должен плодить дубль** (google.js:365-375): повторный `getAll` упал → коды пустые → `id = NaN` → уходит в `addRow` → дубль строки. При сбое чтения — бросать, а не добавлять.
8. **`makeTaskDone` не атомарен**: награда/`hero_money` и запись `task_executions` расходятся при обрыве между шагами (tasks.js:288-298); `todos/updateTodo` не awaited. Деньги начислять после успешной записи выполнения или компенсировать при ошибке; диспатчи awaited.
9. **`toggleTodo` мутирует задачу до подтверждения записи** (TodoList.vue:145 `task.completed=true` прямо на объекте): при сбое `addEvent`/записи локально «выполнено», в таблице — нет; двойной клик → двойная награда (guard от дублей по `task_uuid + день`).
10. **`buyProduct` не транзакционен** (Shop.vue:69-114) и читает баланс из кэша (`getAll` caching=10): стейл-баланс → двойное списание; сбой между шагами → деньги списаны без записи в `rewards_history`. Перечитывать баланс без кэша; при сбое — откат/компенсация.
11. **`JSON.parse` в `loadTodos`/`loadHero`/`loadEvents`/`loadFromStorage`** не защищён: битый/частичный localStorage (после сбоя записи) роняет приложение при старте. try/catch → пустой массив.
12. **`getFreeSlots` не фильтрует невалидные даты**: `new Date(NaN)` ломает сортировку и сравнения (слоты пропадают молча); all-day события (`e.start.date`) парсятся как UTC-полночь и «съедают» слоты утра. Пропускать невалидные, date-only парсить в таймзоне пользователя.
13. **Числовая валидация перед арифметикой**: `repeat_index.toString()` (tasks.js:197) и `task_description.toString()` (TodoList.vue:280) падают на undefined из короткой строки. Использовать `toNumber` (см. «Надёжность»).
14. **Фидбек пользователю**: сообщение об ошибках чтения/записи (ElMessage) вместо тихого `console.error`.

### Оффлайн-очередь действий (outbox)

Принцип: любое действие пользователя выполняется в UI мгновенно и «выглядит как надо» (оптимистично), его снапшот (все вычисленные значения — время, даты, суммы) сохраняется в очередь в localStorage. При проблемах сети/Google/лимитах действие не теряется; когда запись снова возможна, действия уходят в БД **по порядку** (FIFO). Реплей пишет снапшот, а не пересчитывает «на сейчас».

1. **Ядро `Outbox`** в `dnd/static/js/db/` (рядом с `google.js`, общий слой): `enqueue(action)` → localStorage (ключ настраивается), `flush()` по FIFO, `getPending()`, `isRetryableError()`, backoff. `Table` в `google.js` оборачивает записи (`addRow`/`addRows`/`updateRow`/`updateRowByCode`/`deleteRow`), outbox включается опцией `outbox: {key}` на таблице — **по умолчанию ВЫКЛ, dnd не затрагивается**. В todo включается на всех таблицах приложения.
2. **Снапшот вместо пересчёта** — ключевой принцип. В момент действия фиксируются `task_date`, `repeat_index`, `money_reward`, `minutesSpent`, `execution_date`, `execution_time`, `start`/`end` события. Реплей только записывает эти значения в листы. Статистика и расчёт героя на реплее не пересчитываются — они берут время из кэша действий (`execution_date`), а не текущее.
3. **Классификация ошибок**: сеть (TypeError/fetch), 429 (лимиты), 401/403 (после re-auth), 5xx → действие остаётся в очереди; 404/ошибка схемы/битые данные → пометить `failed`, уведомить, из очереди убрать (иначе вечный реплей).
4. **Идемпотентность реплея**: перед `addRow` проверять ключ (`execution_id`, `item_id`, `task_uuid`) — защита от «запись прошла, ответ потерялся» → дубль. `updateRowByCode` идемпотентен по природе (обновляет строку по коду).
5. **Порядок = порядок действий в приложении** (FIFO). Многошаговые операции (`buyProduct`) — каждый шаг отдельным элементом очереди: частичный обрыв самовосстанавливается, порядок сохраняется.
6. **Точки подключения** (обернуть все записи): `todos/updateTodo`, `TodoNew.addTodo`, `hero/updateHero`, `logExecuteTask` (task_executions), `buyProduct` (списание + история + обновление товара), календарь `addEvent`/`updateEvent`/`deleteEvent` и `setTaskToCalendar`. Централизовать создание таблиц (убрать дубли `getGoogleSheetTable` в todos/hero/events и прямые `new Table` в TodoNew/Shop).
7. **Моменты flush**: событие `window 'online'`, таймер 60 с (в `taskAgent`), любая успешная операция (это и есть «подтверждение, что можно писать»), после re-auth, ручная кнопка «Синхронизировать» в настройках.
8. **Backoff при 429/сбоях**: пауза 1с→2с→4с…до 5 мин, попытки лимитированы. Лимит очереди ~500 записей; при переполнении старейшие → `failed` с предупреждением.
9. **UI-индикатор**: бейдж «N действий ожидают сети» + статус последней синхронизации + кнопка «Синхронизировать».
10. **Календарь при оффлайне**: события сохраняют вычисленные `start`/`end` из момента действия; при реплее слот может оказаться занят → вставить в ближайшее свободное место или пропустить с пометкой (дефолт — пропуск, поведение конфигурируемо). `setTaskToCalendar` — каждое событие отдельным элементом очереди.
11. **Взаимодействие с Уст.**: баланс героя и покупки должны браться из локального `hero` (оптимистичный источник правды), а не из стейл-кэша таблицы — иначе значения в очереди разойдутся (завязано на Уст.10).
