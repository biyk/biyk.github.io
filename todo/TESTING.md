# План тестирования todo-проекта

Проект работает и выполняет необходимые задачи. План составлен, чтобы не потерять функционал, не затереть и не сломать данные при внесении правок.

## Принципы

- Одна группа правок → прогон регресса → следующий шаг.
- Никаких записей в боевую Google-таблицу из тестов: тесты работают только с временной копией.
- Текущее рабочее состояние зафиксировано git-тегом `baseline-before-fixes` — точка отката.
- Единый источник истины для тестов расчётов: одни и те же кейсы гоняют и vitest в Node, и кнопка в браузере.

## Шаг 0 — Подготовка (до любых правок)

1. Git-тег `baseline-before-fixes` на текущем чистом состоянии.
2. (Опционально) разовый ручной бэкап боевой таблицы — раз тесты её не трогают, не обязательно, но рекомендуется.

   - скриншоты вкладок (Календарь / Добавить / Магазин / Настройки);
   - `hero_money`, настройки (`todo-settings` в localStorage), статистики (today/week/month/h24/d7, averageCalc/prevAvg/today_points);
   - структуру и счётчики строк листов (первые колонки) — подтвердить/опровергнуть баг #9.

## Шаг 2 — Юнит-тесты в Node (vitest)

Выделить чистые функции из `src/utils/tasks.js` (без изменения поведения), добавив параметр `now` для детерминизма:

- `calcTimeStats(list, now)` — агрегация today/week/month/h24/d7 (выносится из `calcExecutions`);
- `getAverageCalc(list, now)` — среднее по 30 дням, `prevAvg`, `today_points`;
- `computeTaskAdvance(task, now)` — сдвиг `task_date` по `repeat_mode`, нормализация `repeat_index >= 1`, расчёт `money_reward` (используется в `makeTaskDone`);
- `taskSort(task)` — уже чистая.

Инфраструктура:

- `vitest` в devDependencies, скрипт `"test": "vitest run"` в `src/package.json`;
- тесты на мок-данных (без gapi/DOM) в `src/tests/node.test.js` (или адаптер к `cases/tasks.js`);
- тесты фиксируют баги #1–6 как failing → фиксы делают их зелёными.

## Шаг 3 — Кнопка «Запустить тесты» на вкладке «Настройки»

### Поток

1. Кнопка доступна только после авторизации (`!api.expired()`); без авторизации — disabled + подсказка «Требуется авторизация».
2. Клик → lazy `import()` модуля тестов (не раздувает бандл) → статус «Создание копии таблицы…».
3. `gapi.client.drive.files.copy` боевой таблицы (ID из настройки `spreadsheetId`) → `testId`.
4. Прогон всех кейсов против `testId`.
5. `finally { gapi.client.drive.files.delete({fileId: testId}) }` — копия удаляется и при ошибке; если удаление не сработало — лог с ID для ручной уборки.
6. Защита от двойного клика: предыдущая копия чистится до создания новой.

### Файлы

| Файл | Назначение |
|---|---|
| `src/tests/assert.js` | мини-ассерты `ok/equal/throws/deepEqual` — работают в Node и браузере |
| `src/tests/runner.js` | async-раннер: таймауты на тест, сбор отчёта `{passed, failed, skipped, errors}` |
| `src/tests/cases/tasks.js` | чистые расчёты на мок-данных (единый источник с vitest) |
| `src/tests/cases/sheets.js` | интеграционные против копии: шапки листов, первая колонка, счётчики строк, add/update/delete без дублей |
| `src/tests/cases/calendar.js` | read-only: сегодняшние события, дубли по `task_uuid`, валидность TZ |
| `src/tests/node.test.js` | адаптер vitest — переиспользует `cases/tasks.js` |
| правка `src/components/Settings.vue` | кнопка + панель результатов |

### Панель результатов

Счётчик PASS/FAIL/SKIP, длительность, список тестов с ✓/✗, текст ошибки под упавшим тестом; дубль в `console`. Результаты выводятся панелью прямо под кнопкой на вкладке «Настройки».

### Политика безопасности данных

- Read-only тесты — только против копии таблицы, боевая таблица не читается и не пишется тестами.
- Запись-тесты (add/update/delete) — только против копии, после прогона копия удаляется.
- Calendar — только read-only (список событий), записей в календарь тесты не делают.
