# План тестирования todo-проекта

Проект работает и выполняет необходимые задачи. План составлен, чтобы не потерять функционал, не затереть и не сломать данные при внесении правок.

## Статус

Все баги #1–#18 из инвентаризации закрыты (последний коммит `f8f57fff`). В `todo/todo.md` остались только «Улучшения». Дальнейшие правки — только по «Улучшениям», после каждой группы — прогон регресса.

## Принципы

- Одна группа правок → прогон регресса → следующий шаг.
- Никаких записей в боевую Google-таблицу из тестов: тесты работают только с временной копией.
- Точка отката зафиксирована git-тегом `baseline-fixes-done`.
- Единый источник истины для тестов расчётов: одни и те же кейсы гоняют и vitest в Node, и кнопка в браузере.

## Шаг 0 — Подготовка

1. Git-тег `baseline-fixes-done` на текущем чистом состоянии.
2. (Опционально) разовый ручной бэкап боевой таблицы — раз тесты её не трогают, не обязательно, но рекомендуется.
3. Снять baseline для сравнения:
   - скриншоты вкладок (Календарь / Добавить / Магазин / Настройки);
   - `hero_money`, настройки (`todo-settings` в localStorage), статистики (today/week/month/h24/d7, averageCalc/prevAvg/today_points);
   - структуру и счётчики строк листов (первые колонки).

# Блок 1 — Тесты через браузер

Запуск: кнопка «Тесты» на вкладке «Настройки» (раннер `src/utils/tests/index.js`, автоподхват `*.test.js`). Каждый пункт — один тест.

### Кнопка

1. **Доступность кнопки** — кнопка «Тесты» отображается на вкладке «Настройки».
2. **Авторизация** — без авторизации кнопка disabled + подсказка «Требуется авторизация»; после авторизации активна.

### Прогон

3. **Создание копии** — клик по кнопке создаёт копию боевой таблицы (`drive.files.copy`, ID из `spreadsheetId`), статус «Создание копии таблицы…».
4. **Прогон кейсов** — все кейсы гоняются против копии (`testId`), боевая таблица не читается и не пишется:
   - 4.1 **Шапки листов** — в копии совпадают с ожидаемыми.
   - 4.2 **Счётчики строк** — первая колонка/счётчики строк листов не растут лишними дублями.
   - 4.3 **addRow без дублей** — добавление строки в копии не плодит дубли.
   - 4.4 **addRows без дублей** — массовое добавление строк в копии не плодит дубли.
   - 4.5 **updateRowByCode** — обновляет существующую строку, а не добавляет новую (фикс #9).
   - 4.6 **deleteRow** — удаляет нужную строку, остальные не трогает.
   - 4.7 **Сериализация записей** — параллельные записи идут FIFO, не теряются и не перетираются (фикс #15).
   - 4.8 **Кэш колонок по кастомному id** — добавление в копию с кастомным `spreadsheetId` кладёт строку по своим колонкам (фикс #16).
   - 4.9 **Calendar: список событий** — сегодняшние события загружаются.
   - 4.10 **Calendar: дубли по `task_uuid`** — нет событий-дублей по `task_uuid`.
   - 4.11 **Calendar: TZ** — таймзона слотов корректна, ночной сценарий 00:00–04:00 без ошибок (фикс #13).
5. **Панель результатов** — счётчик PASS/FAIL/SKIP, длительность, список тестов с ✓/✗, текст ошибки под упавшим; дубль в `console`.
6. **Уборка копии** — копия удаляется в `finally` (и при ошибке); если удаление не сработало — в консоль логируется ID для ручной уборки.
7. **Защита от двойного клика** — повторный клик чистит предыдущую копию до создания новой, дублей копий нет.
8. **Пустой набор** — при отсутствии тест-файлов показывается «Тесты пока не добавлены».

# Приложение: детали инфраструктуры тестов

## Целевой поток кнопки (браузер)

1. Кнопка доступна только после авторизации (`!api.expired()`); без авторизации — disabled + подсказка «Требуется авторизация».
2. Клик → lazy `import()` модуля тестов (не раздувает бандл) → статус «Создание копии таблицы…».
3. `gapi.client.drive.files.copy` боевой таблицы (ID из настройки `spreadsheetId`) → `testId`.
4. Прогон всех кейсов против `testId`.
5. `finally { gapi.client.drive.files.delete({fileId: testId}) }` — копия удаляется и при ошибке; если удаление не сработало — лог с ID для ручной уборки.
6. Защита от двойного клика: предыдущая копия чистится до создания новой.

## Файлы

| Группа | Файл | Назначение |
|---|---|---|
| Общие | `src/tests/assert.js` | мини-ассерты `ok/equal/throws/deepEqual` — работают в Node и браузере |
| Общие | `src/tests/runner.js` | async-раннер: таймауты на тест, сбор отчёта `{passed, failed, skipped, errors}` |
| Общие | `src/tests/cases/tasks.js` | чистые расчёты на мок-данных — единый источник истины для обеих групп |
| Консоль | `src/tests/node.test.js` | адаптер vitest — переиспользует `cases/tasks.js` |
| Браузер | `src/utils/tests/*.test.js` | кейсы, подхватываемые раннером кнопки (в т.ч. адаптер к `cases/tasks.js`) |
| Браузер | `src/tests/cases/sheets.js` | интеграционные против копии: шапки листов, первая колонка, счётчики строк, add/update/delete без дублей |
| Браузер | `src/tests/cases/calendar.js` | read-only: сегодняшние события, дубли по `task_uuid`, валидность TZ |
| Браузер | правка `src/components/Settings.vue` | кнопка + панель результатов |

## Политика безопасности данных

- Read-only тесты — только против копии таблицы, боевая таблица не читается и не пишется тестами.
- Запись-тесты (add/update/delete) — только против копии, после прогона копия удаляется.
- Calendar — только read-only (список событий), записей в календарь тесты не делают.
